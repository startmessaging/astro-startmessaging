## Chatbots de Menú de Opciones vs. Motores de Procesamiento de Lenguaje Natural (NLP)

Al planificar la automatización de tus chats de WhatsApp, debes elegir la lógica que gobernará las interacciones del asistente virtual. La elección depende del perfil de tus clientes y de los recursos de desarrollo disponibles.

* **Chatbots Estructurados (Basados en Menú):** guían al usuario con botones de respuesta o listas de opciones. Son sencillos de programar, rápidos de validar y resuelven tareas directas (por ejemplo: "Ventas", "Soporte"). Esta lógica disminuye los malentendidos en la conversación.
* **Chatbots Inteligentes (Motores NLP):** utilizan inteligencia artificial (como Dialogflow, OpenAI o Watson) para comprender frases escritas de forma libre. Ofrecen interacciones más humanas, pero requieren ajustes continuos para los modismos del español mexicano (por ejemplo: "quiero saber de mi pedido", "mi paquete no ha llegado", "me urge saber dónde viene").

Para la gran mayoría de las medianas empresas mexicanas, la mejor práctica es un diseño híbrido: botones y listas para el triaje y la resolución transaccional, y la conversación libre o la IA para capturar requerimientos antes de derivar a un asesor.

## Estructura de un Flujo de Atención Conversacional Efectivo

Un flujo bien estructurado debe resolver el problema del cliente con el menor número de interacciones posible, evitando ciclos donde el bot repite respuestas sin dar soluciones.

1. **La Bienvenida:** el bot saluda, se identifica como asistente virtual del negocio y muestra las opciones iniciales.
2. **La Clasificación del Caso (Triaje):** el cliente elige el tema con botones de respuesta (hasta 3) o una lista (hasta 10 filas): Ventas, Facturación o Estatus de Envío.
3. **La Autoatención (Self-Service):** el bot consulta tu base de datos para resolver en tiempo real (por ejemplo: la CLABE para pagos SPEI o la liga de rastreo).
4. **El Escalamiento Humano:** si el cliente pide hablar con un asesor o el bot no entiende dos veces, la conversación pasa a la bandeja de entrada del equipo, con todo el historial visible.

```
+-------------------------------------------------------------+
| Mensaje entrante del cliente en el webhook                  |
+-------------------------------------------------------------+
                              |
                              v
+-------------------------------------------------------------+
| Respuesta del Bot: Bienvenida & Botones del Menú Principal  |
+-------------------------------------------------------------+
            /                 |                 \
           /                  |                  \
          v                   v                   v
+------------------+  +------------------+  +-----------------+
|  Opción Ventas   |  | Opción Facturac. |  | Hablar c/ Asesor|
+------------------+  +------------------+  +-----------------+
          |                   |                   |
          v                   v                   v
[Consulta Catálogo]   [CLABE SPEI / OXXO]   [Bandeja de equipo]
```

Diseñar tu chatbot respetando este flujo incrementa la tasa de resolución automática y disminuye las quejas por mala atención.

## ¿Cómo Funciona la Conexión de Webhooks para Chatbots?

Cuando un cliente escribe al número de tu empresa, StartMessaging hace un `POST` firmado a la URL que registraste en **Developers → Webhooks → Add endpoint**, con el evento `message.received`. El cuerpo siempre tiene el mismo sobre: `id` (identificador del evento, úsalo para descartar duplicados), `type`, `createdAt`, `workspaceId` y `data`.

Cuando el cliente toca un botón o una fila de lista que enviaste, el mensaje llega con `type: "interactive"` y `reply: { kind, id, title }`. Decide con el `id` que definiste, no con el título.

Cada entrega incluye los encabezados `X-SM-Timestamp` y `X-SM-Signature` (`v1=` seguido de un HMAC-SHA256). Verifica la firma sobre el cuerpo crudo y responde con un 2xx en menos de 5 segundos; procesa la lógica después.

## Código: Receptor de Webhooks y Controlador de Bot en Node.js

El servidor Express de abajo verifica la firma, responde de inmediato y luego atiende el mensaje. La función `verificarFirma` sigue el ejemplo de la [documentación de webhooks](/mx/docs/whatsapp/webhooks#verify-signatures).

```javascript
import express from 'express';
import { createHmac, timingSafeEqual } from 'node:crypto';

const API = 'https://waba-api.startmessaging.com/api/v1';
const app = express();
const vistos = new Set(); // en producción, usa tu base de datos o Redis

// rawBody: el cuerpo tal como llegó. secret: el secreto completo "whsec_...".
function verificarFirma(rawBody, headers, secret) {
  const timestamp = String(headers['x-sm-timestamp'] ?? '');
  if (!/^\d+$/.test(timestamp)) return false;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false;

  const esperada = Buffer.from(
    createHmac('sha256', secret).update(`${timestamp}.`).update(rawBody).digest('hex'),
  );

  // Durante la rotación del secreto llegan varias firmas; acepta cualquiera.
  return String(headers['x-sm-signature'] ?? '')
    .split(',')
    .some((parte) => {
      const firma = Buffer.from(parte.trim().replace(/^v1=/, ''));
      return firma.length === esperada.length && timingSafeEqual(firma, esperada);
    });
}

app.post('/webhooks/startmessaging', express.raw({ type: 'application/json' }), (req, res) => {
  if (!verificarFirma(req.body, req.headers, process.env.SM_WEBHOOK_SECRET)) {
    return res.sendStatus(401);
  }
  const evento = JSON.parse(req.body.toString('utf8'));
  res.sendStatus(200); // responde en menos de 5 segundos y luego haz el trabajo

  if (vistos.has(evento.id)) return; // entrega "al menos una vez": descarta duplicados
  vistos.add(evento.id);

  if (evento.type === 'message.received') {
    atenderMensaje(evento.data.message).catch(console.error);
  }
});

async function atenderMensaje(msg) {
  // Clientes con nombre de usuario llegan sin número: respóndeles desde la bandeja.
  if (!msg.from) return;

  const opcion = msg.reply?.id; // el id del botón que enviaste
  const texto = (msg.text ?? '').trim().toLowerCase();

  if (opcion === 'btn_orden') {
    await enviar({ to: msg.from, type: 'text', text: { body: 'Escribe tu número de orden así: orden-1234' } });
  } else if (opcion === 'btn_asesor' || texto === 'asesor') {
    await transferirAAsesor(msg);
  } else if (texto.startsWith('orden-')) {
    await consultarOrden(msg.from, texto.toUpperCase());
  } else {
    await enviarMenuOpciones(msg.from);
  }
}

// Botones de respuesta: hasta 3, título de hasta 20 caracteres (Team en adelante).
async function enviarMenuOpciones(telefono) {
  await enviar({
    to: telefono,
    type: 'interactive',
    interactive: {
      interactiveType: 'button',
      body: '¡Hola! Bienvenido al canal de soporte. ¿Cómo te podemos ayudar hoy?',
      buttons: [
        { id: 'btn_orden', title: 'Rastrear orden' },
        { id: 'btn_asesor', title: 'Hablar con asesor' },
      ],
    },
  });
}

async function consultarOrden(telefono, codigo) {
  // Sustituye por la consulta a tu base de datos
  const info = `Orden ${codigo}:\nEstatus: En tránsito\nFecha estimada de entrega: 18/10/2026\nPaquetería: Estafeta`;
  await enviar({ to: telefono, type: 'text', text: { body: info } });
}

async function transferirAAsesor(msg) {
  await enviar({
    to: msg.from,
    type: 'text',
    text: { body: 'Te transfiero con un asesor disponible. Danos un momento, por favor...' },
  });

  // Asigna la conversación a un miembro del equipo (permiso conversations:write, bandeja en el plan).
  await fetch(`${API}/conversations/${msg.conversationId}`, {
    method: 'PATCH',
    headers: {
      Authorization: `Bearer ${process.env.SM_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify({ assignedToUserId: process.env.ID_ASESOR_GUARDIA, status: 'open' }),
  });
}

async function enviar(payload) {
  const res = await fetch(`${API}/messages`, {
    method: 'POST',
    headers: {
      Authorization: `Bearer ${process.env.SM_API_KEY}`,
      'Content-Type': 'application/json',
    },
    body: JSON.stringify(payload),
  });
  if (!res.ok) {
    const { error } = await res.json();
    console.error(`Error al enviar: ${error.code}: ${error.message}`);
  }
}

app.listen(3000, () => console.log('Receptor de webhooks activo en el puerto 3000'));
```

Las respuestas del bot son mensajes de texto libre e interactivos, permitidos porque el cliente acaba de escribir (la ventana de atención de 24 horas está abierta). Fuera de ella, la API responde `403 MESSAGE_WINDOW_CLOSED` y necesitas una plantilla aprobada.

## Integraciones Recomendadas con CRMs y Helpdesks en México

Para brindar una atención profesional, el chatbot debe estar conectado a los sistemas que ya usa tu negocio.

* **Contactos y embudo en StartMessaging:** cada número que escribe se vuelve un contacto. Con la API actualizas etiquetas y campos personalizados (`PATCH /api/v1/contacts/{idOrPhone}`) y, en el plan Business, mueves al contacto entre etapas del embudo de ventas.
* **CRMs de ventas (HubSpot, Salesforce):** usa el webhook `message.received` para crear o actualizar el prospecto y registrar el origen de campaña.
* **Helpdesks (Zendesk, Freshdesk):** si tu equipo trabaja en un helpdesk, abre el ticket desde el webhook. Si prefieres, la bandeja de entrada compartida de StartMessaging (Team en adelante) muestra al asesor la conversación completa, las etiquetas y los campos del contacto.

## Preguntas Frecuentes

**Q: ¿Es indispensable programar inteligencia artificial compleja para iniciar?**

A: No. Para la mayoría de las consultas recurrentes (estatus de pedido, horarios de sucursal, etc.), un chatbot con botones y listas es más que suficiente. En el plan Business puedes armarlo sin código en el panel.

**Q: ¿Qué tono es el más adecuado al hablar con clientes mexicanos en WhatsApp?**

A: El tono corporativo en México debe ser profesional pero cercano. Se recomienda el trato de "tú" ("¿En qué te puedo ayudar hoy?"), salvo en nichos formales (servicios legales, bancarios o de salud), donde el "usted" sigue siendo la norma.

**Q: ¿Puedo enviar archivos PDF de facturación y cotizaciones de forma automática?**

A: Sí. Envía `type: "document"` con `media.url` apuntando a un archivo público en `https` y, si quieres, `media.filename`. WhatsApp descarga el archivo de tu liga al entregarlo. Los mensajes con archivos también requieren la ventana de 24 horas abierta.

**Q: ¿Meta cobra por los mensajes que envía el bot?**

A: Desde el 1 de octubre de 2026, Meta cobra por mensaje entregado, ya no por conversación de 24 horas. Las respuestas de atención (texto libre, archivos y mensajes interactivos) dentro de la ventana de 24 horas son gratuitas hasta una cuota mensual por número; después, Meta también las cobra. Cada plantilla entregada se cobra, incluidas las de utilidad dentro de la ventana. Si el cliente llegó desde un anuncio de clic a WhatsApp o el botón de una página de Facebook y respondes en menos de 24 horas, se abre una ventana de punto de entrada gratuito de 72 horas. Meta cobra directamente a tu cuenta de WhatsApp Business; StartMessaging no cobra por mensaje. Consulta las tarifas en la [página oficial de precios de Meta](https://developers.facebook.com/docs/whatsapp/pricing).
