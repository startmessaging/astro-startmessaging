### 1. StartMessaging Partner Program (Direct Recurring Referral)

StartMessaging provides a frictionless developer affiliate model. Developers register for a partner link instantly using Google Single Sign-On (SSO). When you refer a client or integrate StartMessaging into a client's application, you earn a 10% lifetime recurring commission on all delivered message spend. 

The client pays StartMessaging directly, and StartMessaging manages DLT infrastructure, operator routing, and client billing. Commissions are calculated on actual delivered traffic and paid automatically on the 25th of every month in Indian Rupees (INR) via UPI or direct bank transfer.

### 2. Twilio Build Partner Program (Enterprise Consulting)

Twilio approaches partnerships through the formal **Twilio Build Partner Program**, designed for enterprise consulting practices (such as Deloitte or Accenture) and system integrators.

Rather than offering simple, self-service referral links for developers, Twilio requires partners to apply for formal program tiers (Registered, Bronze, Silver, Gold). Referral compensation requires submitting "Opportunity Registrations" through the Twilio partner portal for approval prior to client onboarding. Payouts are issued in US Dollars (USD), requiring international vendor onboarding, tax documentation (W-8BEN-E), and wire transfers.

### 3. MSG91 Partner & Reseller Program (Volume Reseller)

MSG91 focuses primarily on a traditional white-label reseller model alongside custom referral arrangements.

To access dedicated reseller management tools and custom price slabs, partners must qualify by maintaining a monthly client volume exceeding 5 lakh (500,000) messages. Under the reseller model, the agency purchases bulk SMS credits, sets up client sub-accounts, handles customer support, and bills end-clients directly. MSG91's referral commission rates are determined on a case-by-case basis rather than published as a flat, transparent percentage.

## Technical Workflow: How Partner Account Attribution & Integration Work

In StartMessaging, partner tracking is designed to be completely zero-maintenance for application code. You do **not** need to pass custom headers or tracking IDs on individual API calls.

### 1. One-Time Account Linking via Referral URL

Attribution occurs when your client creates their StartMessaging account using your unique partner referral link:

```
https://app.startmessaging.com/register?ref=YOUR_PARTNER_ID
```

When the client registers, StartMessaging permanently binds their account ID to your partner referral profile in the database. Alternatively, an existing client can bind your Partner ID inside their StartMessaging dashboard settings under **Organization > Billing > Partner Referral**.

### 2. Clean Application Code Execution

Once account binding is completed, your client’s application code uses the standard StartMessaging Node.js SDK or REST API using their primary API key (`X-API-Key`). No custom headers or tracking parameters are required in production code:

```typescript
import 'dotenv/config';

const STARTMESSAGING_BASE_URL = 'https://api.startmessaging.com';
const API_KEY = process.env.STARTMESSAGING_API_KEY!; // Client's standard API Key

/**
 * Standard OTP dispatch implementation
 * Partner attribution is automatically resolved on the backend via the client's API Key
 */
export async function sendClientOtp(phoneNumber: string) {
  const response = await fetch(`${STARTMESSAGING_BASE_URL}/otp/send`, {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'X-API-Key': API_KEY, // Standard API Key
    },
    body: JSON.stringify({
      phoneNumber,
    }),
  });

  const payload = await response.json();

  if (!response.ok) {
    throw new Error(payload.message || 'OTP dispatch failed.');
  }

  return payload.data;
}
```

Every time this function sends an OTP, StartMessaging's backend identifies the account associated with `X-API-Key`, looks up the bound partner ID, and automatically credits 10% of the delivered message spend to your partner dashboard.

## Evaluating Long-Term Partner Trust, Clawbacks & Attribution Rules

Before recommending an SMS API platform to your clients, carefully review how the platform handles partner attribution, wallet refunds, and payout scheduling.

```

```

### 1. Delivered-Spend Accounting vs. Wallet-Load Clawback Traps

Many traditional CPaaS affiliate programs pay commissions on prepaid wallet top-ups rather than actual message delivery. While receiving an immediate commission when a client loads ₹50,000 into their wallet sounds appealing, it exposes partners to severe clawbacks. If the client requests a partial refund or files a billing dispute, the platform clawbacks 100% of the partner's accumulated earnings.

StartMessaging calculates partner commissions on **actual delivered message traffic**. This eliminates clawback vulnerabilities, ensuring that earned commissions reflect verified, successfully delivered transactions.

### 2. Permanent Account Attribution vs. 30-Day Cookie Expiry

Legacy affiliate portals enforce strict 30-day cookie expiration windows. If a developer introduces a client who signs up today but delays top-up integration by 35 days, the platform wipes the partner attribution, yielding zero commission.

StartMessaging combines a 60-day attribution cookie window with **permanent account binding**. Once a client creates an account using your partner link or referral tag, the client's account is permanently associated with your partner ID, guaranteeing lifetime 10% recurring earnings across all future top-ups and traffic growth.

### 3. Localized INR Payouts (UPI & Bank Transfer)

Global platforms like Twilio issue partner payments in US Dollars, requiring international wire setups, intermediary bank fees ($15–$30 per transfer), and currency conversion losses.

StartMessaging processes all partner payouts in Indian Rupees (INR - ₹) automatically on the 25th of every month directly to your registered UPI ID or Indian bank account, with zero wire transfer fees or minimum threshold barriers.
